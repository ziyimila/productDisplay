# 装修套餐展示小程序 · 设计文档

日期：2026-08-30
状态：已与用户确认（首页方案 A + 材质页方式 ①）

## 1. 背景与目标

装修公司此前用纯文字向客户介绍装修套餐及可选材质，客户难以直观理解。本小程序的目标是让客户（或销售带客时）直观看到：

- 每个套餐的价位（如 498 / 698 / 998 元/㎡）；
- 套餐内每个位置（马桶、瓷砖、地板、木门等）可选哪些品牌；
- 每个品牌下有哪些型号，以及型号的图片、说明和加价；
- 标配 / 升级选配的区分，以及升级加价金额；
- 所选材质的汇总清单和估算总价。

## 2. 用户与场景

- 主要使用者：装修销售在带客讲解时展示；客户自己翻看了解。
- 核心场景：选套餐 → 按位置挑选品牌型号 → 查看型号大图与说明 → 汇总报价。

## 3. 信息架构（已确认的层级）

套餐 Package (498 / 698 / 998)
  └─ 位置/类别 Category (马桶、花洒、瓷砖、地板、木门、橱柜…)
       └─ 品牌 Brand (水净界、九牧、恒洁、箭牌、马可波罗、大自然、梦天…)
            └─ 型号 Model (名称 + 图片 + 说明 + 加价)

规则：
- 每个型号标记为「套餐标配」（含在套餐内）或「升级」（补差价，记录加价金额）。
- 套餐卡片上展示包含的主要品类，以及可选品牌关键词。

## 4. 页面流程（已确认）

1. **首页 · 套餐列表**（方案 A 卡片式）：三档套餐卡片上下排布，含价位、包含品类、可选品牌；点卡片进入该套餐的材质页。
2. **材质页**（方式 ① 同屏对比）：顶部为位置分类横滑条，下面是品牌横滑条；激活品牌下的型号卡片上下排列，「标配」/「+¥升级」标签同屏展示，点型号进详情。
3. **型号详情**：大图 + 多图缩略 + 规格参数（坑距、水效、功能等）+ 产品说明 + 「选这个·加入方案」。
4. **方案清单 · 报价**：面积输入 + 每个位置已选型号汇总 + 基础套餐价与升级差价自动合计，提供「发送方案给客户」入口。

## 5. 技术方案

- 平台：微信小程序，原生框架（WXML / WXSS / JS），无需第三方依赖。
- 数据：先以本地静态数据（data/packages.js）承载套餐/品牌/型号，图片用占位图；数据结构与后续云开发/管理端一致，可平滑迁移。
- 状态：app.globalData 保存当前套餐、各位置已选型号、房屋面积，页面间共享。
- 配色：橙色主色调 #ff6b35（装修行业暖色系），白色卡片 + 浅灰底。
- 目录结构：

  project.config.json
  miniprogram/
    app.js / app.json / app.wxss
    data/packages.js       # 全部展示数据（套餐/类别/品牌/型号）
    images/                # 占位图（后续替换实拍图）
    pages/
      index/               # 首页 · 套餐列表
      materials/           # 材质选择页
      model-detail/        # 型号详情页
      plan/                # 方案清单 · 报价页

## 6. 数据模型（字段约定）

套餐: { id, name, pricePerSqm, tag, categories[], hot? }
类别: { id, name, icon, brands[] }          // 类别内可复用多个品牌
品牌: { id, name }
型号: { id, brandId, categoryId, name, type: "standard"|"upgrade", extraPrice, images[], specs[], desc }
方案: { packageId, area, selections: { categoryId: modelId } }

## 7. 边界与暂不实现（YAGNI）

- 不做管理端 / 云数据库，先固定数据跑通展示（后续迭代再做内容后台）。
- 不做支付、下单、预约、用户登录体系。
- 图片全部用占位块，后续由用户替换为品牌型号实拍图。
- 不做多门店、权限、分享裂变等营销功能。

## 8. 风险与注意

- 小程序上线需微信小程序账号与 AppID（个人主体可注册，类目可选「生活服务/装修」类）。
- 实拍图涉及品牌版权，建议使用授权图或自行拍摄。
- 报价为估算展示，页面注明「最终以实地量房为准」。
